Here is a structured summary of the core literature on **proof optimization and refactoring in Lean 4**, categorized by algorithmic approach, system architecture, and supporting tooling.

---

### 1. Training-Based & Reinforcement Learning Approaches

#### **ProofOptimizer** (*Gu et al., ICLR*)
* **Core Idea:** The first language model system trained specifically to simplify Lean 4 proofs without requiring human demonstration data.
* **Key Mechanisms:**
  * **Symbolic Linter Pre-pass:** Runs a fast symbolic linter to eliminate trivial redundancies (such as dead tactics) before passing code to the LLM.
  * **Supervised Fine-Tuning (SFT) & Expert Iteration:** Fine-tunes a 7B model (Qwen-2.5-7B) on long-short proof pairs generated by Goedel-Prover-V2-32B across 145K theorems. Uses STaR-like expert iteration to sample and filter candidate simplifications.
  * **Online Reinforcement Learning:** Applies asynchronous Group Relative Policy Optimization (GRPO) using a relative token-shortening reward function \\(R(x, y) = \frac{|x| - |y|}{|x|}\\) for verified candidate proofs.
  * **Inference-Time Iterative Shortening:** Repeatedly samples \\(k\\) candidates, picks the shortest compiling output, and feeds it back as the prompt for the next round.
* **Key Findings:** Achieves **87% length reduction on miniF2F** and **57% on PutnamBench**. Resampling/iterative shortening outperforms error-based repair loops, as LLM repairs often introduce verbose tactics that increase proof length.

#### **ImProver & ImProver 2** (*Ahuja et al., Thesis & GitHub*)
* **ImProver 1 (Agentic Approach):**
  * Augments a frontier model (GPT-4o) with **Chain-of-States (CoS) prompting**—annotating intermediate Lean proof states directly into the generation context as comments.
  * Integrates iterative self-debugging error correction and RAG over Mathlib documentation. Demonstrates empirically that proof optimization generalizes standard neural theorem proving when given an empty initial proof.
* **ImProver 2 (Small Language Model + IRPO):**
  * Trains a 7B small language model (DeepSeek-R1-Distill-Qwen-7B) via **Iterative Reasoning Preference Optimization (IRPO)** to eliminate reliance on expensive closed-source models.
  * **Replay Buffer:** Uses a specialized dataset buffer mixing new and old preference pairs to stabilize multi-round RL and prevent model collapse.
  * **Neurosymbolic Scaffolding:** Extractor channels supply AST context slices, CoS traces, and auto-informalization.
  * **Structural Metrics:** Introduces metrics for **modularity** (rewarding non-trivial, effective sub-goal decompositions like `have`/`calc` blocks) and **dependencies** (penalizing explicit calls to external Mathlib lemmas). Outperforms frontier baselines on modularity.

### 2. Controllable & Agentic Strategy Search Frameworks

#### **Lean Refactor** (*Lu et al., 2026*)
* **Core Idea:** A plug-and-play, LLM-agnostic agentic framework that steers frozen LLMs using a densely annotated **Strategy Bank** (9K strategies distilled from 200K long-short proof pairs).
* **Densely Annotated Metadata:**
  * Strategies are annotated with measured **compile-cost reductions** (via `lake env lean --profile`) and validated **Lean/Mathlib toolchain version compatibility** across multiple releases.
* **Multi-Objective Retrieval & Reranking:**
  * Fine-tunes a retrieval model (Qwen3-Embedding-8B) on query-strategy pairs.
  * At inference, retrieval criteria can be dynamically re-configured: shortest proof (top-\\(K\\) cosine similarity), compilation-time aware (retrieve-and-rerank by compile-cost reduction), or version-specific (filtering out incompatible strategies).
* **Agentic Execution Loop:**
  * Coordinates a Planner, Refactorer, and Debugger over any frozen backbone (Gemini, Claude, GPT series).
* **Key Findings:** Delivers **>70% token compression on competition benchmarks** and **>20% on research repositories**. Achieves >30% compilation time savings and produces proofs with superior zero-shot version compatibility across future Lean releases.

#### **Proof-Refactor** (*Fu et al., 2026*)
* **Core Idea:** A four-phase process-guided framework (Extraction \\(\rightarrow\\) Helper Design \\(\rightarrow\\) Proving \\(\rightarrow\\) Proof Repair) focused on modularity and human readability rather than pure proof golfing.
* **Mechanism:** Uses a custom Lean `extract` tactic to lift tactic blocks into standalone theorem scaffolds. External models generalize these scaffolds into clean helper declarations, prove them, and rewrite the primary theorem to invoke them. Driven by Claude Code and `lean-lsp-mcp`.

### 3. Symbolic Dependency Analysis & Metaprogramming DSLs

#### **Tacflow** (*Xin et al., 2025*)
* **Core Idea:** Dynamic analysis framework that infers **Tactic Dependency Graphs (TDGs)** in Lean 4.
* **Mechanism:** Examines proof states before and after tactic executions to track how goals and hypotheses flow. Powers a dead-tactic linter via backward-reachable proof slicing to remove unused code.

#### **LeanSSR** (*Gladshtein et al.*)
* **Core Idea:** Native Lean 4 implementation of Small Scale Reflection (SSR).
* **Mechanism:** Unifies symbolic computation with logical deduction. Allows users to write concise proof scripts using view patterns (` move=> `, `sapply`, `srw`) without manually toggling between Boolean computation and propositional forms, resulting in significantly shorter proof scripts.

#### **Proof Deautomation for Rocq** (*Shi et al., 2025*)
* **Core Idea:** Deautomates opaque script sequences (e.g., `destruct`, `simpl`, `reflexivity`, `first`, `repeat`) into explicit, step-by-step tactics. Uses treeification and failure recovery to unroll scripts up to and beyond error points.

### 4. Cloud Infrastructure & Quality Assurance Tooling

#### **AXLE Infrastructure** (*Xin et al., 2026*)
* **Core Idea:** Cloud infrastructure delivering 14 Lean 4 metaprogramming utilities at scale.
* **Core Tools for Proof Optimization:**
  * `verify_proof`: Strict verification that rejects candidates containing `sorry`, non-whitelisted axioms, or signature/type mismatches.
  * `simplify_theorems`: Deterministic pass that iteratively prunes unused tactics and unreferenced `have` hypotheses.
  * `repair_proofs`: Automatically repairs minor compilation failures in LLM-generated drafts.
  * `have2lemma` / `sorry2lemma` & `merge`: Decomposes partial proofs into sub-lemmas and reassembles them.

#### **Lean Pool** (*Ilin, 2026*)
* **Core Idea:** An AI-maintained repository of formalized mathematics (3.2M+ lines).
* **Mechanism:** Employs continuous integration linters and LLM reviews to automatically upgrade dependencies, refactor proofs for conciseness, and optimize compilation speed and RAM usage across evolving Lean/Mathlib releases.

#### **mathlib-quality & lean-lsp-mcp** (*Birkbeck et al. / Dressler*)
* **`mathlib-quality`:** A Claude Code plugin enforcing mathlib standards. Features `/cleanup` (an 11-phase workflow with 22-item audits, style checks, and diff gates) and `/buzz` (profiling execution time to ensure every declaration elaborates in \\(<1\text{s}\\)).
* **`lean-lsp-mcp`:** An MCP server granting LLM agents sub-second LSP feedback (`lean_goal`, `lean_diagnostic_messages`, `lean_multi_attempt`, `lean_loogle`).

#### **Agentic Proof Automation (System Capless Case Study)** (*Xu & Odersky*)
* **Core Idea:** Case study showing that LLM agents paired with lightweight compiler feedback (`lean4check`) can develop and repair 14,000+ lines of Lean code. Demonstrates that agents excel at mechanical proof repairs following definition/refactoring changes.
